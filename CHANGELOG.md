# Changelog

## 0.7.3 — port and town selection geometry

- Correct ETW-to-NTW slot-footprint winding when adding a Napoleon artwork template. Reverse the packed XY vertex order of land, sea and selection polygons; retain clockwise ordering for legacy slots without a template. No vertex coordinates, port docking points or navigation data are changed.
- Native diagnosis: Napoleon builds template-backed selection prisms with outward normals from counter-clockwise polygons. Earlier exports retained Empire's clockwise polygons, so the prism rejected ray hits and a port click fell through to an invalid terrain movement order. Read-only inspection of a running generated campaign found all 132 ports registered but carrying the incorrect hulls. Disabling the building-scale shader did not resolve the user-reported failure.
- Executed the stock executable's prism builder and ray intersection routines under Unicorn: normal and atlas exports each changed from **0/1,584** accepted port rays to **1,584/1,584** after reversing the hulls, with identical rays and coordinates.
- Added a behavioral regression covering port land/sea/hull selection, outside-point rejection, template-backed towns, empty sea footprints and legacy resource/settlement selection.
- Existing projects and imported originals remain valid. Re-export and reinstall the ZIP to update `regions.esf`; restart the game. No executable patch or building-scale change is required.
- Verification: **460 release tests passed**; release build, published-executable CLI smoke and Clippy completed (non-blocking warnings remain). Full normal and atlas exports succeeded with **680** and **665** game files respectively. Byte-for-byte comparison with 0.7.2 found only `regions.esf` changed: exactly 968 polygon vertex-order corrections across 132 ports and 286 towns, with every other byte in that file preserved.
- The user confirmed docking works in the F-drive game copy after the isolated winding correction. The E-drive modded installation was not changed; install a fresh export there. The F-drive building-scale override remains disabled from the earlier diagnostic comparison.

## Earlier work — project format 9: fixed theatres, activation options, carve

Added
- **GitHub PR checks:** independent Windows Clippy and test jobs run on pull requests and pushes to `main`, pinned to Rust 1.94.1 with locked dependencies and all targets. Actions are commit-pinned, repository permissions are read-only and only main pushes save the dependency cache. Clippy errors block CI; existing style warnings remain non-blocking. Fixed two blocking lints without behavioural changes: the Lua decompiler's constant register allocation and split synthesis's first-failure handling. Both commands pass locally (285 tests), and actionlint validates the workflow.
- **Western America continuity repair.** Source-derived colour and elevation corrections replace the narrow dark-rim match and nearest-height shelf. The join excludes black underlays as colour references, feathers original land over 20 world units and fades the generated correction over 40, without changing the land/sea height mask or theatre geometry.
- Winter snow now continues the source latitude profile and raw-height snowline into western America. Both winter DDS paths and all mip tails are updated; summer remains unchanged. Both America climate rasters continue their own latitude/coast categories, eliminating the invalid India IDs from the second raster while preserving every original climate cell and all winds.
- Colour-only supertexture repairs no longer resample shoreline alpha mips or re-encode unchanged alpha blocks. India's existing repaint output is preserved. The generated-art recipe invalidates older caches automatically; export again to apply the repair.
- Continuity verification: **285 release tests passed** and full/cached native CLI exports succeeded. Decoded colour, relief and snow images were inspected. Boundary height-gradient p95 fell from 4.03 to 2.55 with zero coastline-mask changes; climate seam agreement is 99.91% in both rasters. All 10,544 unchanged texture tiles are byte-identical to the prior native export. No game files were installed and in-game rendering remains unverified.
- **Native local rebuilding replaces distributed game assets.** Import accepts Empire/Napoleon installation roots or `data/` folders. Rust derives mappings, DB rows, localisation, campaign templates, binary UI layouts and Lua scripts from the verified local snapshot plus authored recipes. The GUI starts with imports rather than requiring pre-extracted rules. Both game installations remain read-only.
- Generated rules/UI are published atomically under `workspace/derived/<fingerprint>/assets/`, bound to source hashes, language, schemas and recipes. Published files are hash-checked; no old bundled fallback remains. Source distribution retains only authored policy, MIT-licensed RPFM schemas and public NOAA ETOPO data.
- **Automatic fixed-theatre artwork is painted natively**, not loaded from embedded replacement ZIPs. The first export derives America and India tiles and sparse raw-height repairs from the user's original ETW artwork, public elevation data and calibration. A source/recipe/file-hash-bound cache avoids repainting on subsequent exports; invalid terrain caches regenerate. Heights are patched before relief and fog generation. No external painting, Python, Java or network is needed at runtime.
- Removed the old extracted mapping/DB/localisation/UI assets, terrain bundles and obsolete Python painters/packager. `tools/terrain_paint/prepare_dem.py` remains solely to reproduce the public elevation files; its output reproduced both binaries and calibration byte-for-byte without game files.
- Independent source-only verification: **277 release tests passed**; cold import reproduced all 4,391 original snapshot files. Old/new exports have the same 679 game files, 675 byte-identical; all DB/localisation pack members match. Four Lua scripts differ, with ten executable UI behaviour scenarios passing and six decompilations independently recompiled to matching original bytecode. Actual GUI cold import and export succeeded; its 679 game files match the native cold CLI export exactly.
- Initial native-port terrain parity, before the continuity repair above: all 9,858 untouched tiles and all alpha values preserved; three raw height pixels differ by one byte value, one after default relief, with no coastline disagreement and identical fog. America's fine texture varies with equal-score patch selection (mean absolute RGB error 0.970/255); India differs by 0.000025/255. Decoded renders were inspected; no new campaign was installed or played.
- Export review and CLI retain **`terrain original`** semantics: it skips relief shaping but still includes fixed-theatre repairs. A cached native export equalled the native patched raw heightmap exactly. User project and installed-game inventories stayed unchanged; verification used F: only.
- **Pending ownership is separate from compatibility blockers**: regions whose original ETW owner is not an existing target faction (and that have no saved owner) are reported as `unassigned_regions` instead of one "missing original owner" mapping blocker each. CLI `analyze`/`build`/`resolve list` and the GUI list them as owner selections still to be made; `analyze` still exits 3 and `build` refuses until each region has an existing target faction (`assign --region KEY --faction EXISTING_KEY`). Owner-dependent compatibility checks resume after the recipients are chosen. An explicitly saved owner that is not an existing target faction remains a real error (`ownership:<region>:invalid_owner`). No faction is created, no recipient is chosen automatically and starting forces are still not transferred.
- **Fixed theatre bounds** replace user-configurable rectangles: Europe `[[-180,140],[440,520]]` stays original; India `[[440,-80],[790,300]]` uses the known-working Thailand/Indonesia extent; America `[[-888,0],[-340,460]]` includes every Western Plains outline vertex. Preview and export share one policy; other theatres stay unchanged.
- Removed the Ownership map's **Extend theatre** tool and CLI `theatre set`/`theatre reset`, including their rectangle flags. `theatre list` and the Ownership map's fixed-bounds tooltip are read-only.
- Every export rebuilds the changed theatres' dependent canvases, TGAs, pathfinding, sea grids, clipping and start-position references, even without activations or splits. Unchanged Europe is skipped. Geometry rejects new theatre contacts and overlapping interiors while preserving the original Europe/India shared edge.
- **Multi-area split borders**: overlapping border strips between the same two regions are united before cell generation, and equivalent group-path IDs are canonicalized. An all-area Indochina activation followed by a Mandalay split now exports without overlapping pathfinding pieces or duplicate group paths; users do not need to merge the source areas first.
- **Activation options**: `areas` (`centre` | `all` | indices), `merge` (union of touching areas into one passable area),
  `carve_from` (new region made of one area of a backdrop region). CLI `activate add --areas --merge --carve-from`; the
  activation panel lists/clicks areas, merges and carves.
- **Pathfinding synthesis** for activated / carved regions (land zone, coast band, border bands and group paths, landing
  crossings, settlement node) with the rule checker; **sea-grid lists and connections** regenerated for touched theatres;
  **trade-route guarantee** (every settlement node routed); **start position**: carved CAI region, boundaries for new land
  borders, one HLCI per area of every changed region, camera bounds from the fixed rectangles.
- **Validation pass** at the end of every build (topology, pathfinding membership and rule checker, sea-grid lists, routed
  trade nodes, region list / HLCI / sea-cell counts of the start position); any problem aborts the build.
- The prior India experiment verified selected movement and landing scenarios. The user subsequently confirmed that the combined fixed bounds load and allow expanded camera movement; broader gameplay and the new automatic frame/terrain artwork remain unverified in game. The rule checker rejects every new problem relative to the untouched ETW grid, including America and Europe where the source already has defects.
- Settlement points closer than 2.1 u to the outline of their area are refused (editor and CLI).
- Region splits now also get pathfinding: halves of a split of a chain-activated region are synthesised together after the splits; a split of a region with ETW paths runs `synthesize_split` (side assignment, border band + group path, settlement node).
- `painted_terrain` project field and `terrain set --painted DIR|none`: optional advanced override that imports a supertexture / heightmap / fog mask over the automatic fixed-theatre artwork (below); it must match the fixed geometry and supply matching height and fog.
- `examples/compare_golden.rs`: structural comparison of a generated map against the validated golden files.

Changed
- Faction creation is not supported in any mode. Faction-donor mappings can only select imported target identities, not absent original ETW factions. The direct start-position API rejects non-imported faction keys before generation; generated/curated faction rows cannot expand its allowed identity set. Removed the obsolete recycling-mode flag from export metadata.
- Project files are written as format 9. Versions 1–8 retain their existing migration behavior, but legacy theatre rectangles are discarded in memory; owners, activations, splits and other decisions are preserved. Loading does not rewrite the source project. Explicit saving removes the obsolete `theatres` field, and older editors refuse format 9.
- Export is minimal: imported tables (required and `--with-extras` optional) are conversion/analysis inputs and are no longer all copied into the ZIP. It contains only campaign table additions/overrides, explicit conflict-resolution DB replacements and the merged localisation; the installed target mod supplies unchanged tables (land/naval unit stats, existing faction identities, ...). Import requirements and datasets are unchanged, so no re-import is needed. CLI help, editor text and README now distinguish imported from exported.
- `terrain set` options `--knee`, `--upland-scale`, `--smooth` are now accepted by the command-line parser (they were documented
  but rejected as unknown options).
- `Activatable::passable_area` is optional: a backdrop region without passable area can be activated once its areas are chosen.
